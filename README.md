# FastBid GosZakup

Кроссплатформенное (Windows 10/11, macOS) десктоп-приложение для **скоростной
автоматизированной подачи заявок** на портал госзакупок РК
(`goszakup.gov.kz`) с целевым временем полного цикла 20–50 с.

Python 3.12+, асинхронный стек (`asyncio`, `httpx[http2]`, `websockets`,
`cryptography`) + GUI на `customtkinter`.

---

## 1. Как это работает (ключевая идея)

В момент открытия окна приёма заявок (T0) выполняется **только один сетевой
вызов — финальный submit**. Всё остальное делается заранее, параллельно с
ожиданием T0:

```
 clock → plan → ┌── warmup (подпись + предзагрузка документов) ──┐
                └── watch (адаптивный поллер, таймер T0) ────────┘ → submit → verify
```

| Этап | Что происходит | Типичное время |
|------|----------------|----------------|
| `clock` | синхронизация часов с сервером по `Date`-заголовкам | ~190 мс |
| `plan`  | сборка payload из нишевого шаблона и данных лота | ~40 мс |
| `warmup`| **пакетная подпись всех документов одним вызовом NCALayer** + предзагрузка вложений | ~20 мс + сеть |
| `wait`  | ожидание `TrdBuy.startDate` (T0) | до T0 |
| `submit`| POST заявки с ключом идемпотентности | 2–7 мс + RTT |
| `verify`| подтверждение факта подачи | 0–2 мс |

T0 берётся из данных портала: приём заявок открывается в
`TrdBuy.startDate` (для повторных — `repeatStartDate`) — подтверждено
официальной схемой GraphQL API v3.

## 3. Запуск

```bash
pip install -r requirements.txt

python main.py                      # реальный портал + установленный NCALayer
python main.py --mock --open-after 20   # демонстрация на локальных заглушках
python main.py --selftest --open-after 6  # headless-самопроверка (для CI)
pytest tests/ -q                    # 76 тест
```

`--selftest` печатает отчёт: стадии, `t0_delta_ms`, счётчики портала/NCALayer.

### Сборка GUI-исполняемого файла (.exe)

```bash
pip install pyinstaller tzdata
build_exe.bat        # или: pyinstaller fastbid.spec --noconfirm
```

Результат — **`dist\FastBid.exe`** (~36 МБ, onefile, windowed): автономный
GUI без установленного Python. Пользовательские данные и журнал лежат в
`%APPDATA%\FastBidGosZakup\`. Отладочная сборка с консольным окном:

```bat
set FASTBID_CONSOLE=1
pyinstaller fastbid.spec --noconfirm
```

На macOS сборка аналогична: `pyinstaller fastbid.spec` (получится
`dist/FastBid.app`; для запуска на «чужих» машинах собирайте на самой macOS).

## 4. NCALayer и ЭЦП

* Подключение: `ws://127.0.0.1:13579/kz.gov.pki.knca.basics` (модуль
  `kz.gov.pki.knca.basics`, резерв — `/kz.gov.pki.knca`).
* Конверт: `{"module": "...", "method": "sign", "args": {...}}`.
* **Пакетная подпись**: `args.data` принимает МАССИВ base64-документов — вся
  пачка подписывается **одной операцией**, то есть одним системным диалогом
  вместо диалога на каждый файл (возможность модуля `basics`, осень 2024).
  Для старых версий NCALayer есть автоматический fallback на поштучную подпись.
* Ответ: `{"status": true, "body": {"result": ...}}`; `body` без `result` —
  пользователь отменил операцию; ошибка — `{"status": false, ...}`.
* **Пароль ЭЦП** запрашивается в GUI один раз, хранится строго в оперативной
  памяти (`SecretPassword` на `bytearray` с затиранием нулями), никогда не
  пишется на диск и не попадает в логи.
  ВАЖНО: НУЦ РК не документирует передачу пароля в методе `sign`; подавление
  диалогов «на каждый файл» обеспечивает сам пакетный вызов. Проброс пароля
  в payload включается флагом `ncalayer.pass_password` (для сборок, которые
  его поддерживают, и для mock-тестов).
* БИН/ИИН извлекается из сертификата, встроенного в CMS-подпись
  (`serialNumber` и OID ветки `1.2.398.3.3.4`), и используется для привязки
  лицензии и автозаполнения заявки.

## 5. Аутентификация и достоверность endpoint'ов

### LIVE-режим: вход по токену из браузера (рабочий способ)

Единая платформа закупок (zakup.gov.kz) — закрытый SPA; публичного API входа
для сторонних клиентов у неё нет (SSO-вход по ЭЦП/QR описан только как
пользовательский сценарий). Поэтому в LIVE-режиме приложение использует
**мост через браузер** — тот же механизм, что и документированный OWS v3
(`Authorization: Bearer <token>` из личного кабинета):

1. Способ входа **token** (по умолчанию в LIVE) → «Войти по токену».
2. Войдите в кабинет в обычном браузере (ЭЦП/QR — как всегда).
3. `F12` → Сеть (Network) → обновите страницу → кликните любой запрос к
   `v3bl.goszakup.gov.kz` / `zakup.gov.kz` → заголовки запроса.
4. Скопируйте заголовок `Authorization` (целиком, с `Bearer`) **или** `Cookie`
   (например `SESSION=...`), **или** только токен — парсер принимает любой
   из этих форматов.
5. Вставьте в диалог: приложение проверит токен пингом и перейдёт в
   «Сессия активна». Токен живёт только в RAM; при истечении светофор станет
   красным — вставьте свежий токен той же кнопкой.

### LIVE-режим: вход по ЭЦП (NCALayer)

Способ **ecp** повторяет логику портала:

1. «Войти по ЭЦП» → приложение обращается к локальному сервису НУЦ РК
   (`wss://127.0.0.1:13579`, TLS с самоподписанным сертификатом — это и есть
   транспорт настоящего NCALayer).
2. NCALayer сам показывает окно **выбора ключа** и **сам запрашивает пароль** —
   приложение пароль не спрашивает и не кэширует.
3. Выбранный ключ читается из сертификата (БИН/ИИН, ФИО) и показывается в панели.
4. Далее подписывается challenge кабинета. На живом портале этот шаг пока
   помечен `VERIFY` (публичного API входа у SPA нет) — при отказе приложение
   сообщит об этом и предложит рабочий способ «Токен из браузера».
   На mock-портале (`--mock`) весь цикл проходит целиком.

### Endpoint'ы

* Публичный реестр OWS v3 (`https://ows.goszakup.gov.kz/v3/graphql`) — поля
  `Lots`, `TrdBuy`, `LotsFiltersInput` сверены с официальной схемой:
  <https://ows.goszakup.gov.kz/help/v3/schema/query.doc.html>.
* Публичный OWS работает **только на чтение**; подача заявки — действие
  личного кабинета. Пути кабинета в `config/settings.py` помечены `VERIFY:`.
* Для автономной разработки все пути обслуживает mock-сервер
  (`python main.py --mock`), где работают и ЭЦП-вход, и токен-вход.

## 6. Лицензирование

* Лицензия — JSON, подписанный **Ed25519**-ключом вендора; в поставке только
  публичный ключ. Привязка: БИН/ИИН (из ЭЦП) + HWID (Windows `MachineGuid`,
  macOS `IOPlatformUUID`, Linux `/etc/machine-id`).
* Триал 14 дней, офлайн-грейс, строгая проверка привязки после входа по ЭЦП.

```bash
python main.py --gen-keys      # пара ключей вендора
python main.py --hwid          # HWID клиента
python main.py --issue-license --private-key vendor.pem \
    --bin 123456789012 --target-hwid <HWID> --licensee "ТОО ..." --days 365
```

Блокировка при недействительной лицензии: `FASTBID_LICENSE_ENFORCE=1`
(по умолчанию приложение работает и предупреждает).

## 7. Тесты

`py -3.13 -m pytest tests/ -q` → **76 passed** на Python 3.13.9
(3 тестовых файла, без пропусков): CMS-криптография и извлечение БИН,
пакетная подпись (1 вызов = 1 диалог), fallback на старый NCALayer, отмена
пользователем, проброс пароля, полный цикл с таймингами, отказ до T0
(HTTP 425), идемпотентность повторной подачи, auto-relogin по 401, лицензии
(выпуск/подделка/истечение/привязка), ниши, парсинг дат, синхронизация часов,
регрессии UI/фонового моста, ссылка на карточку через кабинет и mock,
отсутствие connection-specific заголовков в `default_headers()` и ASCII-кодировка
`build_exe.bat`. При отсутствии Tcl/Tk часть UI-проверок пропускается.

Дополнительные проверки:

```bash
py -3.13 -m ruff check .
py -3.13 -m ruff check --select UP041 .
py -3.13 -m ruff format --check .
py -3.13 main.py --selftest --open-after 6
py -3.13 main.py --selftest --dry-run --open-after 6
```

Оба selftest прошли на локальных заглушках. В обычном прогоне выполнен один
submit; в dry-run не было ни загрузок документов, ни submit. Аутентификация
через mock-NCALayer выполняется в обоих режимах. Эти проверки не подтверждают
работоспособность непроверенных LIVE-endpoint'ов и не пересобирают EXE.

## 9. Этика и ответственность

Приложение автоматизирует действия, которые поставщик вправе выполнять сам,
используя собственную ЭЦП. Оно не обходит аутентификацию, не подписывает
ничего от чужого имени и не создаёт нагрузку сверх разумной (поллер имеет
жёсткий пол интервала 150 мс, опрос останавливается после открытия окна).
Ответственность за соблюдение правил портала и законодательства РК лежит
на пользователе.
